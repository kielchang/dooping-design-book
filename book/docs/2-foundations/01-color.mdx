# 色彩語意

Token 的名字說的是「這個顏色代表什麼」，不是「這是什麼顏色」。
所以沒有 `--blue-500`，只有 `--primary`、`--danger`、`--field-editable`。
換品牌色時改的是值，不是任何一行使用它的程式碼。**語意色是唯一的色彩 API，色階不外露。**
值怎麼生成、驗哪些門檻、怎麼新增主題或色票，見[色票配色策略](/foundations/choosing-a-palette)。

## 四組語意，職責不重疊

### 1. 表面與文字（結構）

| Token | 意思 |
| --- | --- |
| `--background` / `--foreground` | 頁面底色與主要文字 |
| `--card` / `--card-foreground` | 卡片表面 |
| `--popover` / `--popover-foreground` | 浮層表面（下拉、泡泡、篩選面板） |
| `--muted` / `--muted-foreground` | 弱化表面與次要文字 |
| `--accent` / `--accent-foreground` | 保留給第三方元件相容；本書元件的 hover／被指向一律走[狀態層](#互動狀態的顏色邏輯)，不用它 |
| `--border` / `--input` / `--ring` | 分隔線、控制項邊框、鍵盤聚焦環 |

深色模式下這五種表面構成**抬升層次**：`background < card < popover < muted < border`。
深色不是把淺色反轉。

### 2. 動作（控制項）

| Token | 用在哪 |
| --- | --- |
| `--primary` | 主要動作（中性近黑，**與色相主題無關**） |
| `--secondary` | 次要動作 |
| `--brand` | 色相主題色：一頁一顆的關鍵動作、品牌強調 |
| `--brand-subtle` | 主題色淡底：選中的導覽項、分頁底線區 |
| `--destructive` | **破壞性動作的控制項**（刪除鈕） |

:::tip `primary` 與 `brand` 分開
`--primary` 維持中性近黑，承擔絕大多數控制項；`--brand` 吃色相主題，
只給一頁一顆的關鍵動作。
見 [深淺主題 → 多色相主題](/foundations/theming)。
:::

### 3. 狀態（訊息與資料）

| Token | 意思 |
| --- | --- |
| `--success` | 良好／已完成／通過 |
| `--warning` | 需要注意，但不阻擋 |
| `--info` | 中性提示／補充說明 |
| `--danger` | 異常／錯誤／不合格 |

每個提醒色的完整定義、使用場景、反例與擴充程序，見[提醒色辭典](/foundations/alert-colors)。

:::tip `destructive` 與 `danger` 分開
一個是「按下去會刪東西」，一個是「這筆資料有問題」。兩者不得混用。
:::

### 4. 欄位（可編輯 vs 唯讀）

| Token | 意思 |
| --- | --- |
| `--field-editable` ＋ `--field-border` | 這一格你可以改 |
| `--field-readonly` | 這一格是算出來的／唯讀 |
| `--edit` / `--edit-bg` / `--edit-foreground` | **已改動未送出**（保留色） |

欄位色與 `edit` 的完整定義同樣收在[提醒色辭典](/foundations/alert-colors)。

## brand 的邊界：不要放在確認按鈕上

`--brand` **不得出現在確認／送出／儲存**這類提交性動作上。兩者職責不同：

| | 職責 |
| --- | --- |
| `--brand` | **識別**：這是誰的產品 |
| 確認按鈕 | **指示可供性**：按下去會提交 |

| 用 `brand` | 用 `primary` |
| --- | --- |
| logo 區、品牌強調 | **確認、送出、儲存、套用** |
| 「開始新流程」這類非提交型入口 | 一般操作 |
| 選中的導覽項（走 `--brand-subtle`） | 取消、返回 |

**提交性動作在任何主題下都用 `--primary`。**

:::warning 近中性色不能拿來做實色填底
`Button` 的停用態是 `disabled:opacity-50`，「停用」的實際外觀就是
`--primary` 以 50% 疊在背景上；近中性的主題色做成填色按鈕會撞進那個位置。

沒有品牌色的主題（預設主題「石墨」）：`--brand` 直接鏡射 `--primary`。
（守衛：`npm run verify:color`，`ΔE00(brand, 停用外觀) ≥ 12`）
:::

## 狀態色與主題色並存：色相、飽和度、面積

主題色與狀態色並存，要守三層：色相、飽和度、面積。

### 一、色相層：警報色域是保留區

四個狀態色佔滿暖色域：`danger 18°`、`destructive 25°`、`warning 71°`、`edit 83°`。
有彩度的 brand（OKLCH chroma ≥ 0.04）色相必須距所有狀態色 ≥25°，可用的區間只有三段：

| 可用區間 | 色系 | 寬度 |
| --- | --- | --- |
| 109°–137° | 綠 | 28° |
| 188°–213° | 青 | 25° |
| 264°–352° | 藍紫 → 洋紅 | 88° |

**0°–95° 一格都不剩。**

不做橙色或金色的主題，即使它的個別色票與 `warning` 的 ΔE00 分得開。

### 二、飽和度層：警報必須是畫面上最飽和的東西

| | OKLCH chroma |
| --- | --- |
| `--danger` | **0.223** |
| `--destructive` | 0.208 |
| `--warning` / `--edit` | 0.165 / 0.164 |
| `--brand`（最飽和的主題） | 0.151 |
| `--primary`（承擔多數控制項） | **0.040** |

這個階序不得反過來：`danger` 的飽和度是 brand 的 1.5 倍、`primary` 的 5.6 倍。

### 三、面積層：高飽和色共用 10%

60% 中性 / 30% 結構 / 10% 高飽和強調——**提醒視窗的關鍵色與圖表的重點色共用那 10%**。

`--primary` 維持中性近黑：畫面上絕大多數按鈕不吃主題色。

### 這三條都由 `npm run verify:color` 擋

新增主題時會逐一檢查色相距離、飽和度階序、與各狀態色的感知距離。
反例：**赤陶 45°**（距 `destructive` 只有 20°，落在警報色域裡）、
**松綠 178°**（距 `success` 只有 16°）都不過。
新增主題的步驟見[色票配色策略 → 新增一組主題](/foundations/choosing-a-palette#新增一組主題)。

:::tip 如果委託方的品牌色就是紅或橙
那就必須二選一：**紅色當品牌，或紅色當警報，不能兩者都是。**

做法：品牌紅只出現在 logo 與登入頁，
進到系統內部之後 `--brand` 改用一個安全區間的色相。
:::

## 提醒視窗：用強度分級，不用更多顏色

四種語意封頂（`success` / `warning` / `info` / `danger`），**不再擴充色相**，
改用同一個語意色的兩種強度：

| 強度 | 樣式 | 用在哪 |
| --- | --- | --- |
| `low`（預設） | `--{狀態}-subtle` 淡底＋**與文字同色**的左粗邊＋圖示＋`--{狀態}-subtle-foreground` | 日常與次要提示 |
| `high` | `--{狀態}` 實色滿版＋`--{狀態}-foreground` 反白字 | **阻斷式**訊息，必須停下來決定的操作 |

**有疑慮就用 `low`。** 提醒視窗的關鍵色與圖表的重點色共用同一份高飽和預算
（**面積 × 頻率**）。

:::warning 淡底不能用「實色壓 10%」做
不要用 `bg-danger/10` 這種寫法；用生成的實色 token `--{狀態}-subtle`，
文字對底色反解到 4.5:1。（守衛：`npm run verify:color` 逐一驗）
:::

### 四種淡底必須彼此分得開

`--{狀態}-subtle` **不做 harmonization**（不往主題色相偏）。

提醒視窗的整體感靠兩件事，**都不是彎色相**：四種共用同一條構成規則
（下一節），以及它們坐在[帶主題色相的中性表面](/foundations/theming)上。

### 「同一層」要等量，不是等參數

淡底的生成參數是**染色量**（`ΔE00(淡底, 卡片表面)`），不是彩度。

規則是兩段的：**四種共用一個明度**；各色相的彩度反解到同一個染色量，彩度不固定。

`npm run verify:color` 有一條門檻：四種染色量的最大／最小比值不得超過 **1.3**。

### 左粗邊用文字色，不用實色

低強度的左粗邊是 `border-l-current`——與內文同色（`--{狀態}-subtle-foreground`），
不是全飽和的狀態色。左粗邊對自己的淡底要達 1.4.11 的 3:1。

## 欄位狀態：三層各司其職

一格欄位可以同時是「被聚焦」「改過沒送」「不合格」。三件事走三個不同的通道：

| 層 | 表達什麼 | 用什麼 |
| --- | --- | --- |
| 聚焦環 | 鍵盤焦點在這裡（控制項語意） | `--ring`，**恆定不隨狀態變色** |
| 邊框＋底色 | 這格的狀態（狀態語意） | 三選一，有優先序 |
| 圖示＋文字 | 為什麼 | `aria-invalid` + `aria-describedby` |

| 狀態 | 邊框 | 底色 | 優先序 |
| --- | --- | --- | --- |
| 唯讀／計算值 | — | `--field-readonly` | — |
| 可編輯 | `--field-border` | `--field-editable` | 0 |
| 已改動未送出 | `--edit` | `--edit-bg` | 1 |
| **不合格** | `--danger` | **不變（不整格染紅）** | 2（最高） |

改過**又**不合格時，邊框顯示 `--danger`；「改過」仍留在變更摘要與復原鈕上。
同一個通道不傳兩件事。

不合格**只動邊框不動底色**。錯誤的主訊號是
邊框＋圖示＋文字（[FormField](/components/input) 把這套固定寫法接好）；
verify:color 有一條門檻盯著邊框對兩種欄位底的對比。

<Rules>
  <Do>
    <p>聚焦環永遠是同一個顏色。</p>
  </Do>
  <Dont>
    <p>不要讓聚焦環跟著驗證狀態變色。</p>
  </Dont>
</Rules>

:::tip 聚焦環一定要有 `ring-offset`
有 offset 時環與元件邊框之間隔一圈背景色，環的 3:1 對**背景**算。
`npm test` 有一條守衛：用了 `ring-ring` 卻沒有 `ring-offset` 的元件直接不過。
:::

「**必填未填**」是不合格的一種：使用者還沒碰過欄位時不標紅，blur 或送出之後才標。

## 互動狀態的顏色邏輯

> **每一個顏色變化都要對應一件使用者需要知道的事，
> 強度與那件事的「持續多久」成正比。**

沒有事實要傳達就不變色；有事實就給到看得見的強度。
強度跟著**持續時間**走，不是跟著重要性走：瞬間的回饋輕，持久的狀態明顯。

### 狀態階梯

| 狀態 | 持續多久 | 傳達什麼 | 走哪個通道 |
| --- | --- | --- | --- |
| hover | 指標在上面 | 這個可以互動 | 中性狀態層 **6%** |
| pressed | 按住的瞬間 | 系統收到了 | 中性狀態層 **14%** |
| focus | 直到移開焦點 | 鍵盤在這裡 | **環**（完全不碰底色） |
| 已選 | 直到改選 | 你選了這個 | 中性狀態層 **20%** |
| 停用 | 直到條件改變 | 現在不能用 | **降低**，不加色（`opacity-50`） |
| 已改動未送出 | 直到送出 | 還沒存 | 狀態色琥珀（見下一節） |
| 不合格 | 直到修正 | 這個值不能用 | 狀態色紅 |

四條規則：

1. **三個互動狀態全部走中性，不吃主題色。**
2. **focus 走「環」這條獨立通道，不碰底色**，可與任何狀態疊加
   （不合格＋聚焦、已選＋聚焦）。
3. **停用是降低，不是加色。** 半透明只留給停用；可用的控制項不做半透明。
4. **已選的列不得再用弱化文字**：已選的列把 `--muted-foreground`
   整個重新定義成 `--foreground`。

### 狀態層是「疊加」，不是「換一組底色」

hover／pressed／已選用疊一層的狀態層（`state-layer`），不換成獨立的實色 token
（`--accent`、`--muted`）。「深了一階」要在每一種底色（頁面底、卡片、`--muted` 斑馬列、浮層）上都成立。

疊加的顏色取元件自己的 `currentColor`，不是統一的 `--foreground`。

所有元件共用狀態階梯的同一組強度（6%／14%／20%）。

### 上限也要驗

門檻裡有一條是**上限**：已選對底色不得超過 ΔE00 16。

門檻對**每一種底色**都驗，不是只驗卡片。
`npm test` 另有兩條程式碼守衛——元件不得寫 `hover:bg-accent`／`hover:bg-muted`，
用了 `state-layer` 的元件不得同時寫 `transition-colors`。

:::tip 唯一的取用端陷阱
不要用 `background` **簡寫**（會把 `background-image` 重設為 `none`，狀態層消失）。
一律用 `background-color`——Tailwind 的 `bg-*` 產的就是 `background-color`。
:::

## 載入中：中性、三種手段各有位置

載入**不是狀態語意**：不進提醒色的彩色家族，一律中性（`--muted` 骨架、變暗遮罩）。

| 情境 | 手段 |
| --- | --- |
| 首次載入、版面已知（清單、卡片、表格首載） | **Skeleton**：反映真實版面的灰塊，版面不跳動 |
| 已有內容、重新查詢（篩選、換頁） | **就地變暗＋資料列脈動＋保留舊內容**（`aria-busy`）；**不蓋骨架**。`motion-reduce` 停動畫，變暗仍在 |
| 提交中（按鈕） | disabled＋換圖示＋改文案（[按鈕沒有 loading 變體](/components/button)） |

<Rules>
  <Do><p>骨架的形狀要<strong>反映真實版面</strong>（列數＝每頁筆數、高度＝實際行高）。
  <code>DataTable</code> 的 <code>loading</code> 已內建這兩種長相的切換。</p></Do>
  <Dont><p>不要在已有資料的畫面上蓋骨架。</p></Dont>
</Rules>

無障礙：載入狀態由**容器**宣告一次（`aria-busy`＋`role="status"` 的 sr-only 文字），
骨架塊本身 `aria-hidden`。
另外[載入中不是空](/components/empty-state)——空狀態是「查完了沒有」，兩者要分得開。

## 保留色：琥珀＝已改動未送出

`--edit` 這一組琥珀色**只做一件事**：標記「使用者改了，但還沒送出」。

不得挪作他用——不能拿來當高亮、當「新功能」標記、當任何其他強調。
完整定義見[提醒色辭典](/foundations/alert-colors)。

## 分類色票與狀態語意脫鉤

圖表的 8 色分類色票（`--chart-1` … `--chart-8`）**不參與**狀態語意。
換一整套圖表色票，不會讓「紅＝異常」跟著變。分類色票也**不跟著色相主題走**——
顏色跟資料實體走，同一個項目在所有圖表、所有主題下都是同一色。

脫鉤是**雙向的**：維度本身就是狀態時（狀態組成堆疊圖），
圖表**必須**沿用狀態色、不得照序取分類色。完整判斷樹見[圖表的配色策略](/components/charts)。

### 分類色與語意色的彩度差異

語意系統**用彩度編碼重要性**：

```
danger 0.223 > warning 0.165 > edit 0.164 > success/info 0.148
       > brand ≤0.151 > primary 0.040 > 中性 ≤0.013
```

分類色票**沒有**這個階序：八色等亮等飽和，彼此平等。
不要為了拉近兩種色票的觀感去調分類色；要管的是**分類色不會被誤讀成狀態色**——見下一節。

### 分類色不得靠近任何狀態色

對六個狀態色全驗，雙條件滿足其一即可：

- 色相拉開 **≥20°**，或
- 感知距離拉開 **ΔE00 ≥18**

擠不下時放寬哪一條，見[色票配色策略 → 門檻優先序](/foundations/choosing-a-palette#門檻優先序)。

### 順序即安全順序

色票的排列不是色相環，是**最遠點插入的順序**：第 1 色錨在藍，之後每一色都是
「與已選色感知距離最遠」的那一個。取用端拿
`--chart-1` … `--chart-k`，對任何 k 都是近似最佳的 k 色子集。

前 k 色的最差一對（含 protan/deutan 模擬的最小 ΔE00）：

| 用到幾色 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 最差一對（淺色） | 57 | 33 | 25 | 19 | 16 | 14 | 13 |
| 最差一對（深色） | 55 | 32 | 26 | 22 | 17 | 15 | 11 |

### 淺色與深色是兩組獨立的值

淺色與深色各一組獨立的值，各自吃滿自己的明度空間（L\* 全距：淺色 34、深色 44），不共用。

:::warning 生成與驗收
色票由 `npm run build:theme` 生成、`npm run verify:color` 驗收，
兩兩感知距離 ΔE00 低於 10 會直接擋 PR。
換色票的步驟見[色票配色策略 → 新增或擴充分類色票](/foundations/choosing-a-palette#新增或擴充分類色票)。
:::

        <code>--chart-{n}</code>

## 對比要求

門檻取 WCAG 2.2 的嚴格值，**不四捨五入**：

| 用途 | 門檻 | 依據 |
| --- | --- | --- |
| 一般文字（按鈕標籤、徽章文字） | 4.5:1 | 1.4.3 |
| 大字（≥18.66px 粗體／≥24px） | 3:1 | 1.4.3 |
| **圖表色塊、邊框、聚焦環** | **3:1** | **1.4.11 非文字對比** |

第三列是 3:1，不是 4.5:1。

淺色與深色**各自**驗一次，並且要驗「該模式裡最不利的表面」而不只是頁面底色
（聚焦環會出現在卡片與浮層上）。

:::warning 對比要在**實際會被畫出來的顏色**上驗
1. **取整之後再驗**（round 成 8-bit 之後）。
2. **對實際的前景 token 驗，不是對理想的白。** 例：`--destructive-foreground` 是
   `210 40% 98%`（微藍的白），不是純白。
:::

## 顏色永遠不是唯一線索

- 狀態徽章要有**文字**
- 變異數字要有**箭頭 ▲▼ 與文字**
- 選中狀態要有**打勾**
- 提示框要有**圖示**

驗收：灰階列印一份，語意不能消失。
