# Coachmark 聚光導引

圈起畫面上的某個元素，旁邊說明它是什麼。

<StoryLink id="元件-引導-聚光導引-coachmark--三步導引" />

## 這是純呈現元件

目標矩形、內容、步進狀態與回呼**全部由外部傳入**。有幾支導覽、目前走到哪、
錨點怎麼找，由宿主應用負責。

## 點穿、縮小、鍵盤

### 1. 聚光洞可以點穿

`pointer-events: none`，使用者仍能點到被圈起來的控制項。
**導引是教人操作，不是代替他操作。**

### 2. 可以縮小

需要實際操作（開對話框、切分頁）時，導引卡收成右下角小膠囊，整個畫面恢復可用。

<Rules>
  <Do><p>導引卡一定要能縮小或移開，而且要讓使用者看得出來可以這樣做。</p></Do>
  <Dont><p>不要做成「只能下一步或關閉」。</p></Dont>
</Rules>

### 3. 鍵盤可以走完

← → 換步、Esc 略過、Enter 前進。每一步自動把焦點移入卡片，
螢幕報讀器透過 `aria-live` 唸出新內容。

## 驗收模式

同一個元件換一種用途：加上 `showVerdict`，每一步多一組「✅ 通過／❌ 有問題＋備註」。
走完就是一份可交付的驗收報告。

## 四種形態

除了「圈住某個元素」之外，這個元件還有四種形態：

| 形態 | 什麼時候 |
| --- | --- |
| **無錨點置中卡**（`targetRect` 傳 `null`） | 開場與收尾。此時沒有任何特定元素要圈 |
| **互動待點**（`actionHint`） | 這一步必須使用者真的動手，導覽才能往下 |
| **狀態警示**（`warning`） | 前置條件沒滿足，照著做會失敗 |
| **鏈結下一支**（`secondaryAction`） | 走完一支，銜接下一支 |

### 開場與收尾不要硬找一個東西圈

導覽的第一步是「這段導覽要帶你做什麼」，最後一步是「你已經會了」。

<Rules>
  <Do><p>開場與收尾傳 <code>targetRect = null</code>，卡片置中，不畫聚光洞。</p></Do>
  <Dont><p>不要為了「每一步都要有聚光」而隨便圈一個標誌或標題。</p></Dont>
</Rules>

### 需要動手的那一步，要說出來

需要動手的步驟（開啟對話框、切換分頁、輸入一個值）不能只用「下一步」帶過。

<Rules>
  <Do><p>用 <code>actionHint</code> 明說（「👆 點上方圈選處即可繼續」），
  並讓實際操作也能推進到下一步。</p></Do>
  <Dont><p>不要只留「下一步」按鈕就期待使用者會自己去點圈起來的地方。</p></Dont>
</Rules>

### 前置條件沒滿足要先講，不要讓他撞牆

<Rules>
  <Do><p>用 <code>warning</code> 在<strong>該步的卡片上</strong>講明白：
  現在的狀態、為什麼不能做、去哪裡解除。</p></Do>
  <Dont><p>不要讓使用者照著導覽做，然後撞到一個「無法操作」的錯誤。</p></Dont>
</Rules>

### 最後一步接下一支

`secondaryAction` 在末步多一顆次要按鈕（「接著看：⟨下一段流程⟩ →」）。

<Rules>
  <Do><p>每支導覽聚焦一件事（3–7 步），走完再鏈結到下一支。</p></Do>
  <Dont><p>不要為了「一次講完」把三個流程串成 15 步。</p></Dont>
</Rules>

主按鈕維持「完成」——**離開的路要永遠比繼續的路好走**。「接著看」不當主按鈕。

## 何時不要用

<Rules>
  <Do><p>第一次使用的關鍵路徑（3–7 步）、或新功能公告（1–2 步）。</p></Do>
  <Dont><p>不要用導覽來補救糟糕的介面。</p></Dont>
</Rules>
