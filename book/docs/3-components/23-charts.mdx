# Charts 圖表

**一組零相依的 SVG 圖表**：不裝任何圖表庫，直接用 token 的色票畫。
八種圖各自回答一個問題，超出這八個問題的需求不做。

<Demo title="八種圖都是真元件（資料是行內宣告的兩鍵示範值）">
  <div className="grid max-w-3xl gap-6 sm:grid-cols-2">
    <BarChart
      title="各單位數量"
      showValues
      data={[
        { label: "甲單位", value: 420 },
        { label: "乙單位", value: 250 },
        { label: "丙單位", value: 610 },
        { label: "丁單位", value: 180 },
      ]}
    />
    <Bullet label="本期進度（目標＝上限）" value={640} target={800} />
  </div>
</Demo>

<StoryLink id="元件-資料-圖表-charts--互動">互動 playground——可切圖表類型與資料點數</StoryLink>

## 邊界：這組元件不適合什麼

<Rules>
  <Do><p>後台的<strong>閱讀型</strong>圖表：一眼看懂現況、必要時點一下鑽取到明細清單。
  資料點數<strong>百位數以內</strong>。</p></Do>
  <Dont><p>不要拿來做<strong>分析型</strong>互動：縮放、刷選（brush）、十字游標讀值、
  圖內鑽取後再鑽取。真的需要，請直接用成熟圖表庫，不要改造這組。</p></Dont>
</Rules>

| 限制 | 說明 |
| --- | --- |
| 資料量 | SVG 逐點渲染，**上千個節點就會卡**。超過約 500 點請改 canvas 方案，或先在資料層彙總 |
| 互動 | 只有 hover 提示與 `onSelect` 回呼。**沒有**縮放、刷選、拖曳、圖內編輯 |
| 軸 | 只畫必要的基準線與端點值，沒有完整刻度系統、沒有雙 Y 軸（Pareto 的累積線是唯一例外） |
| 即時 | 沒有串流／動畫過場。資料換了就重畫 |

## 何時用哪種圖

先問「這張圖要回答什麼問題」，再挑圖種。**不要先挑圖種再想要放什麼。**

| 使用者的問題 | 意圖 | 用哪種 |
| --- | --- | --- |
| 誰比較多／比較少？ | 比較 | `BarChart` |
| 是不是少數幾項佔了大部分？ | 集中度 | `Pareto` |
| 這個總量是由哪些部分組成的？ | 組成 | `StackedBar` |
| 隨時間怎麼變？ | 趨勢 | `TrendChart` |
| 實際離目標還有多遠？ | 達成率 | `Bullet` |
| 這兩個數值有關係嗎？ | 相關性 | `Scatter` |
| 兩個維度交叉起來，哪裡集中？ | 分布（二維） | `Heatmap` |
| 前 20% 拿走了多少？ | 累積分布／不均程度 | `LineChart`（配對角基準線） |

<Rules>
  <Do><p>一張卡片<strong>一張圖、一個問題</strong>。旁邊用一句話寫結論
  （<a href="/components/callout">Callout</a> 或圖表卡的說明列）。</p></Do>
  <Dont><p>不要把兩個問題疊在一張圖上，拆成兩張。</p></Dont>
</Rules>

### 不提供圓餅圖

要看組成 → `StackedBar`。
要看集中度 → `Pareto`。

## 八種圖

以下每一種都列出：**用途 · 何時不要用 · 資料形狀 · 可調參數**。
資料形狀用共同型別：

```ts
type BarDatum = { label: string; value: number; id?: string };
type Segment  = { label: string; value: number; color: string };
type Point    = { x: number; y: number; label?: string; id?: string };
```

### BarChart 長條圖

**比較同一個量在不同類別間的大小。**

<Rules>
  <Do><p>類別 <strong>3–12 個</strong>、標籤短、只有一個量要比。</p></Do>
  <Dont><p>類別是時間（月份、週）→ 用 <code>TrendChart</code>。</p></Dont>
</Rules>

```tsx
<BarChart data={[{ label: "北區", value: 1_200_000 }, …]} showValues maxItems={12} />
```

| 參數 | 作用 |
| --- | --- |
| `data` | `BarDatum[]` |
| `showValues` | 在長條頂端標數值。**列印與觸控裝置一定要開** |
| `maxItems` | 類別上限，超過時彙總成「其他（N 項）」 |
| `valueFmt` | 數值格式器 |
| `onSelect` / `selectedIndex` | 點擊鑽取（由宿主渲染明細清單）與選取態 |
| `color` / `height` | 單一序列色、高度 |

### Pareto 柏拉圖

**長條由大到小 ＋ 累積百分比折線。** 回答「前幾項就佔掉多少」。

<Rules>
  <Do><p>要做取捨排序時用：先處理哪幾項最划算（ABC 分析、退回原因、呆滯項目）。</p></Do>
  <Dont><p>類別之間<strong>本來就差不多</strong>時不要用。</p></Dont>
</Rules>

累積線是本組唯一的「雙軸」，但不畫第二條 Y 軸刻度：累積值只在提示裡以百分比呈現。

| 參數 | 作用 |
| --- | --- |
| `data` | `BarDatum[]`（元件內部自行由大到小排序，宿主不必先排） |
| `maxItems` | 同上，超過彙總成「其他」 |
| `onSelect` | 點擊鑽取 |

### StackedBar 水平堆疊長條

**看一個總量由哪些部分構成**，同時比較多個總量。

<Rules>
  <Do><p>分段 <strong>2–6 段</strong>，且各段語意固定（每一列的第 1 段永遠是同一件事）。</p></Do>
  <Dont><p>不要放 8 段以上。細碎項目請先在資料層合併成「其他」。</p></Dont>
</Rules>

每一列右側**固定顯示總量數字**。

| 參數 | 作用 |
| --- | --- |
| `rows` | 每列 `label` ＋ `segments: Segment[]`（顏色由宿主指定，見〈配色策略〉） |
| `onSelectRow` / `selectedRow` | 整列點擊鑽取與選取態 |
| `height` | 單列高度 |

<Demo title="每列右側固定顯示總量；圖例配 Legend">
  <div className="max-w-md space-y-2">
    <Legend items={[
      { label: "甲類", color: "var(--chart-1)" },
      { label: "乙類", color: "var(--chart-2)" },
      { label: "丙類", color: "var(--chart-3)" },
    ]} />
    <StackedBar
      title="各單位分類組成"
      rows={[
        { label: "甲單位", segments: [
          { label: "甲類", value: 120, color: "var(--chart-1)" },
          { label: "乙類", value: 80, color: "var(--chart-2)" },
          { label: "丙類", value: 40, color: "var(--chart-3)" },
        ] },
        { label: "乙單位", segments: [
          { label: "甲類", value: 60, color: "var(--chart-1)" },
          { label: "乙類", value: 150, color: "var(--chart-2)" },
          { label: "丙類", value: 30, color: "var(--chart-3)" },
        ] },
      ]}
    />
  </div>
</Demo>

### TrendChart 趨勢折線

**同一個量隨時間怎麼變。**

<Rules>
  <Do><p>x 軸是<strong>等距的時間</strong>（每月、每週）。至少 3 個點。</p></Do>
  <Dont><p>x 軸不是時間、或間距不等（例如只有幾個不連續的日期）→ 用 <code>BarChart</code>。</p></Dont>
</Rules>

`zeroBased` 預設 **true**（Y 軸從 0 起算）。

<Rules>
  <Do><p>金額、數量這類「絕對量」一律 <code>zeroBased</code>。</p></Do>
  <Dont><p>只有在看「相對變化」且已明確標示起訖值時才關掉。關掉時務必讓兩端數值可見。</p></Dont>
</Rules>

| 參數 | 作用 |
| --- | --- |
| `data` | `BarDatum[]`（`label` 當 x 軸刻度） |
| `zeroBased` | Y 軸是否從 0 起算（預設 true） |
| `valueFmt` | 端點值與提示的格式器 |
| `onSelect` / `selectedIndex` | 點擊某期鑽取該期明細 |

### Bullet 子彈圖

**實際 vs 目標，一條就講完。**

<Rules>
  <Do><p>單一指標的達成率（預算執行、SLA、配額）。放在卡片頂端當摘要。</p></Do>
  <Dont><p>不要一次排十條當主要視覺；改用 <code>BarChart</code> 並排序。</p></Dont>
</Rules>

**這是唯一使用狀態色的圖**：超出目標走 `--danger`、未超出走 `--success`，
不用分類色票。

「超出」是好是壞由宿主決定語意；本元件預設「目標＝上限」（例如預算）。
指標是「目標＝下限」（例如營收）時，由文案講清楚紅色代表什麼。

| 參數 | 作用 |
| --- | --- |
| `value` / `target` | 實際值與目標值 |
| `label` | 指標名稱 |

### Scatter 散布圖

**兩個數值之間有沒有關係。**

<Rules>
  <Do><p>兩軸都是連續數值、點數 <strong>20–300</strong>、你真的想看相關性。</p></Do>
  <Dont><p>點數少於 10 不要用。點數上千也不要用（見〈邊界〉）。</p></Dont>
</Rules>

軸範圍取自資料的 min/max（不從 0 起算）。必須標 `xLabel` / `yLabel`。

| 參數 | 作用 |
| --- | --- |
| `points` | `Point[]`，`label` 用於提示 |
| `xLabel` / `yLabel` | 軸說明（**必填**） |
| `onSelect` | 點擊某點鑽取該筆 |

### Heatmap 熱圖

**兩個維度交叉之後，值集中在哪裡。**

<Rules>
  <Do><p>列 × 欄都是<strong>類別</strong>（區域 × 分類、月份 × 項目），格子數在 100 以內。</p></Do>
  <Dont><p>維度值很多（50 × 50）不要用；改用排序後的清單或 <code>Pareto</code>。</p></Dont>
</Rules>

**`null` 代表無資料，不是 0。** 元件會把 `null` 畫成灰底並顯示 `—`，
圖例也會註明「灰＝無資料」。

| 參數 | 作用 |
| --- | --- |
| `rowLabels` / `colLabels` | 兩軸類別 |
| `cells` | `(number \| null)[][]`，維度為列 × 欄 |
| `domain` | 色階值域。**不給就依當期資料自動取 min/max** |
| `fmt` | 格內數值格式器 |
| `legend` | 是否顯示色階圖例（預設開） |
| `onSelect` | 點格鑽取 |

<Rules>
  <Do><p>要<strong>跨期比較</strong>時務必手動指定 <code>domain</code>。</p></Do>
  <Dont><p>不要在多張並排的熱圖上各自用自動值域。</p></Dont>
</Rules>

<Demo title="null 畫成灰底＋「—」，跟 0 分得開">
  <Heatmap
    title="單位 × 分類數量"
    rowLabels={["甲單位", "乙單位", "丙單位"]}
    colLabels={["甲類", "乙類", "丙類", "丁類"]}
    cells={[
      [120, 45, null, 8],
      [60, 150, 12, null],
      [null, 30, 95, 0],
    ]}
  />
</Demo>

### LineChart 累積分布折線

**累積比例曲線**，配對角基準線看「離平均分布差多遠」。

<Rules>
  <Do><p>看不均程度：前 20% 的往來對象貢獻了多少金額、前 20% 的項目佔多少結存值。</p></Do>
  <Dont><p>不要拿來畫時間序列——那是 <code>TrendChart</code>。</p></Dont>
</Rules>

| 參數 | 作用 |
| --- | --- |
| `points` | `{ x, y }`，**兩者都必須先正規化到 0–1** |
| `diagonal` | 是否畫對角基準線（完全平均分布） |

曲線離對角線越遠＝越集中。

### Legend 圖例

色塊 ＋ 文字標籤的清單。**色塊永遠不會單獨出現。**

```tsx
<Legend items={[{ label: "通路 A", color: PALETTE[0] }, { label: "通路 B", color: PALETTE[1] }]} />
```

只有多序列的圖（`StackedBar`）需要圖例。單序列的圖不要放圖例。

## 配色策略：先問資料形態，再問維度語意

畫任何一張圖之前，顏色的來源由這棵判斷樹決定。
**顏色永遠回答同一個問題**：使用者在徽章上學到的「綠＝完成」，到了圖表裡不能變成別的意思。

```
資料是連續數值嗎？
│
├─ 是，單向（量的大小）──▶ Sequential：單色相染色量
│     Heatmap 就是這層（PALETTE[0] 染色量 8–78%）。跨期比較鎖 domain。
│
├─ 是，雙向（好壞偏差）──▶ Diverging：語意色相淡階，中性中點
│     danger-subtle ←── muted ──→ success-subtle
│     兩極亮度對稱；值域對稱（-max, +max）讓中點對齊零。
│     這是 Delta 的紅綠邏輯在連續資料上的延伸。
│
└─ 否（離散類別）──▶ 三層，依序判斷：
      ① 語意：維度值已有系統語意（狀態、好壞、變更）→ STATUS_SERIES
      ② 身分：維度會跨圖表、跨期別反覆出現      → colorByKey
      ③ 區辨：一次性比較                         → PALETTE 照序
```

序列色一律從 token 取（`--chart-1` … `--chart-8`，見[色彩語意](/foundations/color)；
選色程序見[怎麼選一組分類色票](/foundations/choosing-a-palette)）。
狀態色語意的正本在[提醒色辭典](/foundations/alert-colors)。

### 第 1 層【語意】：維度本身就是狀態時，必須沿用狀態色

維度值本身就是系統語意時（狀態組成、好壞分佈、變更與否），不得照序取 `PALETTE`。

```tsx
import { STATUS_SERIES } from "@/components/dooping/base";

// 狀態組成堆疊：done=success、confirmed=info、void=danger
segments: [{ label: "已完成", value: 12, color: STATUS_SERIES.success }, …]
```

<Rules>
  <Do><p>語意堆疊用 <code>STATUS_SERIES</code>（**淡底**）。實色版 <code>STATUS_SERIES_STRONG</code>
  只給線、點這類小面積。這與 <a href="/components/badge">Badge</a>「預設淡底、實色給例外」是同一條強度語法。</p></Do>
  <Dont><p>不要把狀態維度餵給 <code>PALETTE</code>，也不要反過來拿
  <code>--success</code> 當一般分類色。</p></Dont>
</Rules>

### 第 2 層【身分】：反覆出現的維度，顏色跟實體走

同一個類別在**所有圖表、所有期別**必須是同一個顏色。

```tsx
import { colorByKey } from "@/components/dooping/base";

// 鍵清單是「維度的定義」：宿主宣告一次、所有圖表共用，與當期資料無關
const UNITS = ["甲單位", "乙單位", "丙單位", "丁單位"] as const;
<BarChart color={colorByKey("乙單位", UNITS)} … />
```

<Rules>
  <Do><p>依<strong>固定的類別鍵清單</strong>決定色索引。清單寫在宿主的常數裡，
  超過 8 個或找不到的鍵自動退 <code>muted</code>。</p></Do>
  <Dont><p>不要依「當期數值排序後的名次」配色，包括照當期陣列順序取
  <code>PALETTE[i]</code>。</p></Dont>
</Rules>

同一實體的**子狀態**（預估 vs 實際、本期 vs 上期）用**同色相降階**
（透明度或淡階），不佔第二個色票位。

### 第 3 層【區辨】：一次性比較才照序取用

維度沒有語意、也不會反覆出現時，`PALETTE` 照序取用即可。

**超過 8 類不加色、要強調不換色：**

```ts
// 超過封頂：取前 N-1 名，其餘彙總成「其他（N 項）」
const shown = capItems(data, 8);
```

- **不要循環取色**。`BarChart` 與 `Pareto` 內建 `maxItems`（預設 12），
  其他圖種在資料層先彙總
- **要強調某一類：highlight ＋ mute**——選取後其餘淡化（`selectedIndex`
  已內建：其餘降到 35% 不透明度）。不要為了強調把某類換成更鮮豔的色相
- `Pareto` 例外：單一顏色、不做分類配色

## 空資料、單點、全零

| 情境 | 元件行為 | 宿主要補什麼 |
| --- | --- | --- |
| **空資料**（`data.length === 0`） | 顯示一行「無資料」，**不畫空白座標軸** | 用 [EmptyState](/components/empty-state) 說清楚是「還沒有資料」還是「篩選後沒有結果」 |
| **單一資料點** | 畫出該點並置中，不畫線 | 若圖表標題寫著「趨勢」，此時應改顯示單一數值 |
| **全部為零** | 座標軸正常，所有長度為 0（內部以 `Math.max(1, …)` 保底避免除以零） | **明說「本期皆為 0」** |
| **值全部相同**（熱圖） | 色階值域自動撐開，避免整張同色 | 若這在業務上有意義，用文字說明 |

<Rules>
  <Do><p>「沒有資料」和「資料是 0」要能分辨。前者用空狀態，後者畫出來並註明。</p></Do>
  <Dont><p>不要讓兩者都變成空白區塊。</p></Dont>
</Rules>

## 無障礙：顏色不能是唯一線索

- **直接標示**優先於圖例：`StackedBar` 每列右側標總量、`BarChart` 開 `showValues`
- 圖例一定有文字
- 相鄰序列取色票**兩端**
- 分段數壓在 6 以內
- 提示內容不是唯一出口

<Rules>
  <Do><p>每一張圖旁邊都要能拿到<strong>數字本身</strong>——同一份資料的
  <a href="/components/data-table">DataTable</a> 或 CSV 匯出。</p></Do>
  <Dont><p>不要讓某個數字<strong>只存在於圖裡</strong>。</p></Dont>
</Rules>

### 文字等價：`role="img"` 的義務

通則在[無障礙四原則](/accessibility/principles)：
`role="img"` 掛了就必須用文字補回（WCAG 1.1.1，Level A）；
文字出口用 `sr-only` 表格、不做 SVG 焦點管理；數值已在鄰近可見文字時圖形改標 `aria-hidden`。

各圖種的做法：

| 圖種 | 做法 |
| --- | --- |
| `BarChart`／`Pareto`／`TrendChart`／`LineChart`／`Scatter` | `aria-label` 摘要（由資料自動生成）＋ 一份 `sr-only` 的 `<table>`（`<caption>`＋`scope`），列出精確數值 |
| `StackedBar`／`Bullet` | 數值**已在鄰近可見文字**（列標籤＋合計／實際＋目標＋差額）→ 圖形標 `aria-hidden`；`StackedBar` 的分段明細改由整體表格提供 |
| `Heatmap` | 本來就是真表格（數值是可見文字、顏色只是輔助）→ 不加額外表格，改補正表格語意（`caption`／`scope`／列標頭用 `<th scope="row">`） |

### 鍵盤等價：資料表兼任操作介面

hover 提示與點擊鑽取能做的事，鍵盤使用者也要做得到（WCAG 2.1.1，Level A）。
**不做** SVG 焦點管理，讓文字等價的那張資料表**兼任鍵盤介面**：

- 有 `onSelect` 的圖，資料表的每一列是一顆**真按鈕**，Enter 觸發同一個鑽取回呼
- 資料表平常 `sr-only`，**鍵盤焦點進入時現形**（同 skip-link 慣例）

用 Tab 走到下面這個活範例就看得到：

## 列印

圖表用 `currentColor` 與 token 變數上色，列印樣式下會跟著主題走。
兩個注意事項：

- 部分印表機預設**不印背景色**，長條與色塊會消失：要列印的圖用直接標示（`BarChart` 開 `showValues`，`StackedBar` 每列標總量）。
- 圖表卡片套 `print-block`（`break-inside: avoid`）。
  見[列印與匯出](/patterns/print-and-export)。

## 取用

```bash
npx shadcn@latest add https://kielchang.github.io/dooping-design-book/r/charts.json
```

一個 item 帶走整組：八種圖＋`Legend`＋共同底座（型別、`PALETTE`、`capItems`、
文字／鍵盤等價表）。相依只有 `@dooping/tokens`（色票與軸線變數）與 `utils`（`cn`）——
沒有圖表庫、沒有 d3、沒有 canvas polyfill。

抄進宿主後的匯入長這樣：

```tsx
import { BarChart } from "@/components/dooping/bar-chart";
import { PALETTE, capItems } from "@/components/dooping/base";
```

（守衛：`npm run verify:color` 驗這 8 色的分類色票——彼此的色覺障礙 ΔE00、對四種底色的對比、不得靠近六個狀態色）
