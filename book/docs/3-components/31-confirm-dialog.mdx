# ConfirmDialog 確認對話框

[Dialog](/components/dialog) 的「破壞性動作分三級」規範，做成固定寫法的元件。

<StoryLink id="元件-浮層-確認對話框-confirmdialog--一般確認" />

## 用途

中、高後果動作的確認：標題講動作、描述講後果、確認鈕的字是**動詞**。
搭配 `useDialogState` 管一個畫面裡多種對話框的開關（天然單開、同值再設即關）。

## 何時不要用

<Rules>
  <Do><p>後果不可逆或影響範圍大的動作：作廢、送出鎖定、批次刪除。</p></Do>
  <Dont><p>可復原的低後果動作<strong>不要跳確認</strong>，直接執行＋就地提供「復原」。
  分級判準見 <a href="/components/dialog">Dialog</a>。</p></Dont>
</Rules>

## 狀態

三個行為契約，每一條都有 play function 驗收：

1. **確認後不自動關閉**：成功才關、失敗留在原地顯示錯誤，時機由宿主在
   `onConfirm` 的後續決定。元件不吃 Promise；async 編排與錯誤呈現由應用層負責。
2. **`loading` 鎖住所有出口**：確認、取消、Esc、點遮罩、右上關閉一律無效。
3. **`typeToConfirm` 硬確認**：輸入指定字串才解鎖確認鈕。
   只用於影響半徑最大、完全無法還原的操作（[硬鎖定](/patterns/hard-lock)在對話框層的做法）。

## 無障礙

- 繼承 Dialog 的全部保證：焦點鎖定、`aria-modal`、標題與描述的 aria 連動。
- `loading` 時確認鈕帶 `aria-busy`，讀屏要唸得到「處理中」。
- 硬確認的輸入框走 Label 連動，錯字時按鈕維持 disabled，不另顯示紅字錯誤。
