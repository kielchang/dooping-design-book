# 硬鎖定與明確解鎖

**適用**：經過「確認」之後要凍結的單據或期間。

**確認＝資料凍結。要改，必須先明確解除確認。**

```
未確認 ──確認──→ 已確認（凍結）
                      │
                      └──明確「取消確認」──→ 未確認（可改）
```

## 三層守衛，缺一不可

### 1. 資料層守衛（權威）

所有寫入操作在資料層檢查鎖定狀態，**已鎖定就直接 no-op**，不回傳錯誤。

### 2. UI 預攔

按下去之前就擋，並寫明原因與解法：「此筆已確認，需先取消確認才能修改」。

### 3. 視覺標示

鎖定的欄位顯示鎖頭，而且**仍然可以聚焦**；鎖定原因要讀屏唸得到。

## 規則

<Rules>
  <Do>
    <p><strong>解鎖是一個明確動作</strong>，並記錄誰、何時、為什麼解鎖。</p>
  </Do>
  <Dont>
    <p>不要做「編輯自動解除確認」。</p>
  </Dont>
</Rules>

<Rules>
  <Do><p>解除確認時<strong>連帶處理衍生資料</strong>（例如刪掉當期的凍結快照），
  重新確認時再重建。</p></Do>
  <Dont><p>不要只改狀態旗標。</p></Dont>
</Rules>

## 實作

- 鎖定判定寫成**一個函式**（`isLocked(period)`），資料層與 UI 共用同一份邏輯
- 所有 mutation 開頭第一行就是這個守衛，不要散在各處
- 寫一個測試：對已鎖定的資料呼叫每一個 mutation，斷言狀態完全不變
  （**人工：取用端的資料層**——本書沒有資料層，這條在本 repo 沒有守衛，靠取用端自己的測試）
