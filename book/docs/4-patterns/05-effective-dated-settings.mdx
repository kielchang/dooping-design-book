# 生效日版本化設定

**適用**：會進入歷史計算結果的設定（費率、稅率、係數）。

**參數不是一個值，是一串帶生效日的版本。** 某個期間用哪一版：「生效日 ≤ 該期間」的最後一版。

```ts
type Versioned<T> = { effectiveFrom: string; value: T }[];

// 取某個期間該用哪一版：「生效日 ≤ 該期間」的最後一版
function resolve<T>(versions: Versioned<T>, period: string, fallback: T): T {
  const hit = versions.filter((v) => v.effectiveFrom <= period).at(-1);
  return hit?.value ?? fallback;
}
```

```
版本清單          2024-01 起 3.0%
                 2024-07 起 3.5%

2024-03 的報表 → 解析到 3.0%
2024-08 的報表 → 解析到 3.5%
```

## 哪些設定要版本化

| 設定 | 要版本化？ |
| --- | --- |
| 會進入**歷史計算結果**的（費率、稅率、係數） | ✅ 必須 |
| 只影響**當下顯示**的（頁面大小、預設排序） | ❌ 不必 |
| 影響**未來行為**但不回溯的（通知規則） | ❌ 一般不必 |

## 三條實作規則

### 1. 計算層不吃版本清單

```
✅  calculate(input, { feeRate: 0.03 })      ← 已解析的值
🚫  calculate(input, { feeRateVersions })    ← 讓計算層自己去挑
```

計算層保持純函數，只吃已解析的值。

### 2. 所有消費端一律依期間解析

報表、試算、匯出、圖表——每一個地方都走同一個 `resolve()`，不直接讀「最新值」。

### 3. 就地編輯要有守衛

<Rules>
  <Do>
    <p>要改參數 → <strong>新增一個生效版本</strong>，生效日必須晚於最後一個已鎖定期間。</p>
  </Do>
  <Dont>
    <p>不要直接改最新版本的值，如果它的生效區間已經涵蓋了已鎖定的期間。</p>
  </Dont>
</Rules>

使用者要改一個「已被歷史引用」的版本時，UI 引導他去「新增生效版本」，不只是擋下來。
