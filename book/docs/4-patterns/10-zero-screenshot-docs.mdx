# 零截圖文件示意

**適用**：操作手冊與文件裡的畫面示意——一律不用截圖。

## 做法：用真元件排出示意圖

```
重點控制項  →  元件庫的真元件 ＋ <Spotlight> 圈起來
其餘區域    →  <Placeholder> 佔位留白
整體版面    →  <MockScreenFrame>
```

<Demo title="示意圖是用真元件排出來的">
  <div className="overflow-x-auto rounded-lg border">
    <MockScreenFrame>
      <div className="flex items-center gap-2">
        <TabPills value="confirmed" onChange={() => {}} tabs={[{ key: "all", label: "全部" }, { key: "confirmed", label: "已確認" }]} />
        <span className="ml-auto"><Spotlight label="① 先切到「已確認」"><Badge variant="info">7 筆</Badge></Spotlight></span>
      </div>
      <MockRow />
      <MockRow focus={<Spotlight><Button size="sm" variant="outline">排程處理</Button></Spotlight>} />
    </MockScreenFrame>
  </div>
</Demo>

## 三條規約

<Rules>
  <Do><p>重點包 <code>Spotlight</code>（真元件），其餘一律 <code>Placeholder</code>。</p></Do>
  <Dont><p>不要用 Placeholder 去「假裝」一個真元件。</p></Dont>
</Rules>

<Rules>
  <Do><p>聚光用<strong>與系統內導覽同一套視覺</strong>（同一個 <code>.spotlight-ring</code>）。</p></Do>
  <Dont><p>不要在文件裡另外設計一套紅框箭頭。</p></Dont>
</Rules>

<Rules>
  <Do><p>把「禁止截圖」寫成<strong>守衛測試</strong>。</p></Do>
  <Dont><p>不要只靠 code review 的自律。</p></Dont>
</Rules>

## 示意圖畫到哪裡

示意圖表達「**該點哪裡**」，不做像素級復刻。一張示意圖表達一步；其餘依要表達的東西選：

- 跨步流程：[多步流程播放器](#多步流程播放器)（把每一步各排一張圖，串起來）
- 「點下去是什麼手感」：[嵌入的 story](#互動示意什麼時候該嵌-storybook)
- 拖曳與連續動畫：短影片

## 多步流程播放器

<Callout variant="info" title="這一節是規範，播放器元件還沒收">
  `packages/react` 還沒有這支元件；做多步流程時，自己排幾張示意圖依序陳列。
  元件層的細部規約見
  [Mockup 的〈播放器的元件層規約〉](/components/mockup#播放器的元件層規約)。
</Callout>

把同一條流程的每一步各排一張示意圖，放進一個播放器。

```
<MockFlow name="batch-review" />
   ├─ ① 切到「已確認」分頁            ← 示意圖 1（聚光在分頁）
   ├─ ② 勾選要處理的列                ← 示意圖 2（聚光在勾選欄）
   ├─ ③ 按「送出批次」                ← 示意圖 3（聚光在按鈕）
   └─ ④ 完成後你會看到：狀態變成「已排程」 ← 示意圖 4（聚光在狀態徽章）
```

每一張仍然遵守上面的三條規約（真元件 ＋ `Spotlight` ＋ `Placeholder`）。

### 自動輪播，但要能停

預設每 4.2 秒換一步，**滑鼠移入就暫停**。有自動輪播就必須有 hover 暫停。

### 「展開全部」與列印共用同一套展開樣式

標頭放一顆切換鈕：展開全部 → 所有步驟同時顯示、各自帶字幕、停止輪播。

```css
/* 螢幕：只顯示當前步 */
.flow-step { display: none; }
.flow-step.is-active { display: block; }

/* 展開全部：螢幕上的展開狀態 */
.flow-expanded .flow-step { display: block; }
.flow-expanded .flow-controls { display: none; }

/* 列印：同一個展開狀態，不另寫一套 */
@media print {
  .flow-step { display: block !important; }
  .flow-controls { display: none !important; }
}
```

細節見[列印與匯出](/patterns/print-and-export)第 9 條。

### 每條流程都要有直達入口

流程標頭放一個連到系統對應畫面的連結（「開啟此作業」）。

## 互動示意：什麼時候該嵌 Storybook

要表達「點下去的手感」（展開收合、切換狀態、輸入時的即時回饋）時，嵌一個**可操作的元件**：

<StoryFrame id="元件-資料-資料表-datatable--完整功能" title="資料表：搜尋、篩選、排序、分頁" height={460} />

`iframe` 指向隨文件一起發佈的 Storybook。上面那一框的寫法：

```tsx
<StoryFrame id="元件-資料-資料表-datatable--完整功能" title="資料表" height={460} />
```

| 要表達什麼 | 用什麼 |
| --- | --- |
| 這個畫面長怎樣、該點哪裡 | 靜態示意圖（[Mockup 積木](/components/mockup)） |
| 一連串步驟 | 多步播放器（見上節） |
| 這個元件操作起來是什麼感覺 | 嵌入 Storybook story |
| 實際資料長什麼樣 | 直達入口連到系統本身 |

### 嵌入一定要有守衛

文件裡的每一個嵌入引用（story id）都要由守衛核對存在。
本書的守衛是 `tests/doc-hooks.test.ts`：掃出文件裡的每一個嵌入引用，
與 stories 檔推導出的合法 id 集合比對，指向不存在的 story 就紅。
做法與失敗訊息的寫法見[漂移防護的第 7 支](/governance/drift-guards)。

### 列印時換成替代說明框

列印時把 `iframe` 換成一個說明框，明講「這裡原本是可操作的展示」，
不印空框、不直接隱藏。規則見[列印與匯出](/patterns/print-and-export)第 8 條。

## 延伸：文件站嵌真元件

讓文件站**直接編譯並渲染元件庫原始碼**（本頁的示意圖就是真的 React 元件）。
做法見 [治理 → 漂移防護](/governance/drift-guards)。
