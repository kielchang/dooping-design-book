# 功能開關

**適用**：已經寫完、測過、能跑，但**現在還不該給使用者看到**的功能。

## 做法：純布林開關，只隱藏入口

```ts
export const FEATURES = {
  /** 存量清查（清查作業畫面 ＋ 設定分頁 ＋ 結算頁的參考數量） */
  quantityCheck: false,
  /** 任務追蹤（時數拆分／成本／完成預估 ＋ 工作台的超額警示） */
  taskTracking: false,
} as const;
```

### 1. 只隱藏入口，不刪程式碼、不刪資料、不動計算

被關掉的功能，它的**一切都留著**：

- 狀態切片、示範資料
- 純函數（計算、彙總），連同它們的測試照常跑
- 元件與畫面（Storybook 仍可預覽）
- 資料庫欄位與既有資料

**唯一被拿掉的是使用者走得到的路。**

### 2. 純布林，與環境脫鉤

開關的值是寫死的 `true` / `false`，**所有環境一致**。

<Callout variant="warning" title="不依環境決定">
  **開關不得與環境綁定。** 驗收的畫面必須就是使用者會看到的畫面。
</Callout>

開發時要看到被關掉的功能：**改那一行布林值**（改完自己看，不提交），
不要讓程式自己依環境決定。

### 3. 把 gating 點列成清單

**功能的入口不只有側邊欄那一個**。gating 點：

- 側邊欄項目
- **路由本身**
- **未知路徑的 fallback**（不能落在被關掉的畫面）
- 其他畫面的**跨功能引用**（工作台待辦、彙總報表的某一區、結算畫面的參考數值）
- 設定頁的分頁
- 說明內容

<Rules>
  <Do><p>加開關時，用<strong>全庫搜尋</strong>找出所有引用該功能的地方，逐一決定要不要 gate，
  並把清單寫進開關檔的註解。</p></Do>
  <Dont><p>不要只藏側邊欄就宣告完成。</p></Dont>
</Rules>

### 4. 前置條件：先證明核心數字零依賴

關掉一個功能之前，先確認**核心計算結果不會因此改變**。

```
被關掉的資料 ──?──> 核心計算
                    （若有依賴，關功能＝改數字，那不是關功能，是改行為）
```

驗證方式：搜尋核心計算與選取器對那些資料的引用，確認是**零**。
不是零的話，先把依賴切乾淨，或者不要用開關解決。

這條檢查的結果建議寫進提交說明。

### 5. 邊界要定義精確

同名的東西不見得屬於同一個功能。

例：關掉「任務追蹤」功能之後，主檔裡那個叫「任務類別」的**自由文字欄位**、
以及報表裡依它分組的功能，**都留著**——它是獨立的分類維度，只是同名。

<Rules>
  <Do><p>在開關的註解裡寫明<strong>它不包含什麼</strong>。</p></Do>
  <Dont><p>不要靠關鍵字搜尋決定範圍。</p></Dont>
</Rules>

### 6. 重啟＝改一個布林值

驗收標準：**把 `false` 改成 `true`，功能完整回來，不需要其他改動。**

隱藏一律靠開關，不靠刪除或註解。

## 開關的維護與測試

- 被關掉的程式碼照常維護。
- 每個開關的註解寫明**誰決定的、為什麼、什麼條件下打開**。打開條件必填。
- 測試不必跑兩套：核心計算已證明零依賴（第 4 條）時，
  只要加測「開關關閉時導覽與路由仍然正確」，其餘測試沿用原本那一套。

## 規則

<Rules>
  <Do><p>開關的粒度＝<strong>一個使用者認得的功能</strong>。</p></Do>
  <Dont><p>不要用開關包單一按鈕或單一欄位。</p></Dont>
</Rules>

<Rules>
  <Do><p>關閉的功能在<strong>元件層仍然可被預覽</strong>（Storybook），
  設計與實作可以繼續推進。</p></Do>
  <Dont><p>不要因為「反正關掉了」就停止維護它的 story 與測試。</p></Dont>
</Rules>
