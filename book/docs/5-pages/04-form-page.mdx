# 表單頁

**一次把一件事填完。** 表單頁服務「建立一筆新的」；
修改既有資料是[明細頁](/pages/detail-page)逐欄編輯的事——這條分工先記住，
後面的規則都是從它長出來的。

## 何時用

| 情境 | 用什麼 |
| --- | --- |
| 建立一筆新紀錄 | **表單頁** |
| 修改既有紀錄的欄位 | 明細頁的[逐欄編輯](/patterns/inline-field-editing) |
| 兩三個欄位的輕量輸入（改名、填備註） | [Dialog](/components/dialog) 內嵌小表單 |
| 一長串有順序依賴的輸入 | 表單頁的**多步驟**變體（見下） |

<Rules>
  <Do><p>一頁一件事：標題直接說出那件事（「建立項目」），填完送出就離開。</p></Do>
  <Dont><p>不要做「一頁改十件事」的萬用表單。什麼都能改的畫面，
  使用者每次都要重新掃一遍才找得到要改的那格。</p></Dont>
</Rules>

## 欄位怎麼排

<Rules>
  <Do><p>依<strong>使用者回答問題的順序</strong>分組——「這是什麼」一組、「數量與管道」一組，
  一組一張卡。組織原則與長表單拆法見<a href="/patterns/scenario-request-form">情境化申請單</a>。</p></Do>
  <Dont><p>不要照資料表欄位順序從上排到下。資料模型的順序是給程式看的，
  40 個欄位平鋪的表單是給人受苦的。</p></Dont>
</Rules>

<Rules>
  <Do><p>一欄式優先：視線直直往下走。欄位窄且相關（如數量＋金額）才併排。</p></Do>
  <Dont><p>不要為了「看起來緊湊」排三欄。Z 字形的視線路徑讓漏填率變高，
  而且 Tab 順序與視覺順序容易對不上。</p></Dont>
</Rules>

必填標示全站一種寫法（標在 Label 上），可選欄位不標——反過來標「（選填）」
的前提是必填佔多數。兩種都標等於都沒標。

## 錯誤的位置

跨頁一致性守則第 4 條在表單頁的展開：

- **行內錯誤緊貼欄位**：`aria-invalid` ＋ 欄位下方的紅色小字（`aria-describedby` 連起來）。
- **頂部只做彙總**：用 [Callout](/components/callout)（warning）列「有幾個欄位待補」，
  不重複每一條錯誤內容。
- **時機**：blur 或送出後才標紅。使用者還沒碰過的欄位就標紅，
  是在懲罰還沒發生的錯（[輸入控制項](/components/input)的既有規則）。

## 動作區

<Rules>
  <Do><p>主要動作在右、取消在左；送出中把按鈕停用＋換「處理中…」文案。
  取消要有離開防呆：表單有內容時按取消，先用 Dialog 確認「要放棄這份表單？」。</p></Do>
  <Dont><p>不要做「重設」按鈕。誤觸的代價（整張白填）遠大於它的用處，
  而且它長得跟「取消」太像。</p></Dont>
</Rules>

送出成功的回饋去向全站固定一種：跳轉到新紀錄的明細頁、或就地
`Callout live`（success）——選一種，寫進團隊的驗收清單（Toast 尚未收錄，
見[缺件表](/pages/overview)）。

## 多步驟變體

<StoryFrame id="頁面-表單頁--多步驟" title="多步驟：Stepper＋分步內容＋末步總覽" height={640} />

**拆步的門檻**：欄位有順序依賴（先選單位才知道有哪些選項）、或單頁超過三組。
純粹欄位多但彼此獨立，用分組卡就好——翻頁本身也是成本。

<Rules>
  <Do><p>步驟 ≤5、每步標題是名詞短語、可回上一步且<strong>已填內容不丟</strong>；
  末步永遠是總覽確認，送出前看得到全部要送的東西。</p></Do>
  <Dont><p>不要在中間步驟就寫入資料。「填到第三步就已經建立了草稿」會留下
  一堆半成品紀錄，而使用者以為自己按了取消就什麼都沒發生。</p></Dont>
</Rules>

Stepper 的可點回跳、目前步驟標示見 [Stepper](/components/stepper)；
第一次使用的引導疊加見[引導式導覽](/patterns/guided-tour)。

## 無障礙

- 每個輸入都有 `Label`（`htmlFor` 綁定）；錯誤用 `aria-invalid`＋`aria-describedby`。
- 頂部彙總 Callout 加 `live`，錯誤數量變化時螢幕閱讀器唸得到。
- Tab 順序＝視覺順序；動作區永遠是最後兩個停留點。
- 多步驟的目前步驟要以文字呈現（「第 2 步，共 3 步」），不能只靠顏色。

## 缺件與替代

替代寫法見[頁面總覽的缺件表](/pages/overview)。在那之前，錯誤標示照本頁
「錯誤的位置」一節的固定寫法手排，不要各畫面自創。
