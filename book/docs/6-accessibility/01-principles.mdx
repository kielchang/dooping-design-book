# 四條原則

## 1. 觸控目標 ≥ 44px（粗指標裝置）

```css
@media (pointer: coarse) {
  .tap-target   { min-height: 44px; min-width: 44px; }
  .tap-target-y { min-height: 44px; }
}
```

**只在粗指標裝置生效**：手機平板放大，桌機維持精簡尺寸。

`tap-target-y` 只放大高度：用在分頁膠囊、標籤片這類「寬度由內容決定」的元素。

## 2. 鍵盤要能走完全部流程

| 規則 | 說明 |
| --- | --- |
| **Roving tabindex** | 一組選項只佔**一個** Tab 停留點，組內用方向鍵移動 |
| **Esc 一律可退出** | 展開的編輯、浮層、導覽都要吃 Esc |
| **focus-visible** | 聚焦環只在鍵盤操作時出現，滑鼠點擊不顯示 |
| **焦點不能消失** | 元素被移除時要把焦點交還給合理的位置 |

<Rules>
  <Do><p>四個選項的分段選擇＝<strong>1 個</strong> Tab 停留點。</p></Do>
  <Dont><p>不要讓四個選項各佔一個停留點。</p></Dont>
</Rules>

## 3. 對比：WCAG AA，淺深各驗一次

- 一般文字 **4.5:1**、大字（18px+ 或 14px 粗體）**3:1**
- UI 元件邊界 **3:1**
- **深色模式要分開驗**
- 驗的時候要用**真正的頁面背景**，不是色票研究時的比較背景

## 4. 顏色不是唯一線索

| 元件 | 第二條線索 |
| --- | --- |
| 狀態徽章 | 文字 |
| 變異顯示 | ▲▼ 箭頭 ＋ 文字 |
| 選中狀態 | ✓ 打勾 |
| 提示框 | 固定圖示 |
| 負數金額 | 會計括號 `($2,000)` |
| 鎖定欄位 | 鎖頭圖示 |

驗收方法：**把畫面用灰階印出來**，語意要仍然完整。

## 額外：鎖定的元素仍要可聚焦

```tsx
<div role="group" tabIndex={0} aria-disabled aria-label="信用額度，$1,500,000（已鎖定：此筆已結案）">
```

`disabled` 的原生元素**無法被聚焦**。鎖定的元素用 `aria-disabled` ＋ `tabIndex={0}` ＋ 把原因寫進 `aria-label`；
鎖定原因要讀屏唸得到。

## 額外：圖形化內容的文字等價

**適用**：用 SVG 畫出來、而且**承載了資訊**的東西——圖表、流程示意、進度環、狀態分布圖。

### `role="img"` 不是中性標記

`role="img"` 同時做兩件事：

```
1. 把這個節點當成一張圖
2. 讓它的子樹對輔助技術隱藏 ← 這件事很少被提到
```

圖裡用 `<text>` 畫出來的類別名稱、數值、軸標籤，**螢幕報讀器一個都讀不到**。
掛上 `role="img"` 就**必須用文字補回被隱藏的資訊**。

這是 WCAG 1.1.1（非文字內容），Level A。

<Rules>
  <Do><p>掛 <code>role="img"</code> 就<strong>同時</strong>給 <code>aria-label</code>：
  一句話說出這張圖在講什麼、範圍多大、最值得注意的是什麼
  （「各單位數量長條圖，共 6 個單位，最高為甲單位 1,240」）。</p></Do>
  <Dont><p>不要只寫 <code>aria-label="圖表"</code>。</p></Dont>
</Rules>

### 文字等價用表格，不要去做 SVG 焦點管理

摘要之外，精確數值要另外給：

| 做法 | 評估 |
| --- | --- |
| 讓 SVG 內的資料點可以逐個聚焦、逐個播報 | **不建議** |
| 附一份 `sr-only` 的 `<table>`（`<caption>` ＋ `scope`） | **建議** |

**不要為了無障礙去發明一種新的瀏覽方式，用已經存在而且大家都會的那一種（表格）。**

<Rules>
  <Do><p>同一份資料的表格出口，同時給<strong>鍵盤使用者</strong>與
  <strong>拿到列印版的人</strong>用：懸停提示裡的數值，表格裡都要有。</p></Do>
  <Dont><p>不要讓任何一個數字<strong>只存在於圖裡</strong>。
  懸停提示不能是唯一出口。</p></Dont>
</Rules>

### 數值已經在旁邊時，圖形要 `aria-hidden`

有些圖的數值**本來就是可見文字**：橫向堆疊條旁邊的列標籤與合計、
子彈圖的實際值與目標值、以顏色輔助的資料表。這時不再加一份文字等價。

| 情況 | 做法 |
| --- | --- |
| 資訊只在圖形裡 | `role="img"` ＋ 摘要 ＋ `sr-only` 表格 |
| 數值已在鄰近可見文字 | 圖形標 **`aria-hidden`**，讓可見文字負責 |
| 本體就是表格、顏色只是輔助 | 不加圖形語意，改把**表格語意補正確**（`caption`／`scope`／列標頭用 `<th scope="row">`） |

判準：**同一筆資料，在無障礙樹裡只能出現一次。**

<Rules>
  <Do><p>把圖形標 <code>aria-hidden</code> 之前，先確認可見文字<strong>真的涵蓋了全部資訊</strong>。
  只列了合計而分段明細只在圖裡的話，明細仍然要有出口。</p></Do>
  <Dont><p>不要用 <code>aria-hidden</code> 當偷懶的出口。</p></Dont>
</Rules>

### 已知限制要明講

懸停提示與點擊鑽取若只有滑鼠拿得到（資料點沒有 `tabIndex` / `onKeyDown`），
即不符 WCAG 2.1.1（鍵盤），Level A：**要寫進文件當成已知限制**。

建議的解法：**讓那份表格兼任鍵盤介面**（表格列可觸發同一個鑽取動作），
不回頭去做 SVG 的焦點管理。
