# 導入三階段

不要一次全上。每個階段都要能**單獨停下來**而不留爛攤子。

<FlowAdoptionStages />

（這一頁適用**既有系統**；全新專案直接從[頁面章](/pages)選頁型起手。）

## 階段一：只導 token（1–2 天）

```bash
npm install @dooping/tokens
```

```css title="Tailwind v4：全域 CSS"
@import "tailwindcss";
@import "tw-animate-css";
@import "@dooping/tokens/tokens.css";
@import "@dooping/tokens/tailwind.css";
```

```js title="Tailwind v3：tailwind.config.js"
presets: [require("@dooping/tokens/tailwind-preset")]
```

既有的 v4 專案若已有 shadcn 產生的 `:root`／`.dark` 色值與 `@theme inline` 對映：
**整段刪掉**，換成上面兩行 `@dooping/tokens`。

做什麼：把硬編色換成語意 token。

```diff
- className="bg-red-50 border-red-200 text-red-700"
+ className="bg-danger-subtle border-danger/30 text-danger-subtle-foreground"
```

**可以停在這一階段。**

## 階段二：新畫面用元件（持續）

規則：**新做的畫面用工具箱的元件，舊畫面不動。**

```bash
npx shadcn@latest add https://kielchang.github.io/dooping-design-book/r/data-table.json
```

## 階段三：導入模式（按需）

模式不一次導入，**遇到問題時再查**：

| 遇到 | 讀 |
| --- | --- |
| 「使用者常改壞主檔」 | [唯讀逐欄編輯](/patterns/inline-field-editing) |
| 「確認之後還能改，出過事」 | [硬鎖定](/patterns/hard-lock) |
| 「不知道誰改了什麼」 | [稽核與回復](/patterns/audit-and-restore) |
| 「改參數把歷史報表弄壞了」 | [生效日版本化](/patterns/effective-dated-settings) |
| 「新人不會用」 | [引導式導覽](/patterns/guided-tour) |
| 「印出來很醜」 | [列印與匯出](/patterns/print-and-export) |
| 「手冊的截圖過期了」 | [零截圖文件示意](/patterns/zero-screenshot-docs) |

硬鎖定、生效日版本化會改變業務流程，導入前先取得共識。

## 三個階段之外：建立守門機制

不管走到哪一階段，都要有人負責看門。見 [RFC 流程](/governance/rfc)。

導入之後：元件算不算遵循、想改上游怎麼辦，見[符合性台帳](/governance/conformance-ledger)；
怎麼知道上游出新版、要不要跟、怎麼跟，見[跟上新版](/governance/staying-current)。
