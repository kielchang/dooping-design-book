# Inline Field Editing

## Problem

A master form has 30 fields, but users usually open it to change one. A wall of inputs makes changed fields hard to identify, lets a mouse wheel accidentally modify numbers, and makes active data look like an unfinished draft.

## Approach

**Read-only by default; open one field at a time.**

```
Read-only (looks like a value, with a faint pencil)
   ↓ click
Editing (real input, auto-focused)
   ↓ change value
Changed (amber field + “Changed” label + undo)
   ↓ Esc / blur
Read-only (amber remains)
```

| Requirement | Why |
| --- | --- |
| Discoverable read-only cue (faint pencil) | Users know the value is editable |
| Mark the whole field when changed | A scan reveals every changed field |
| Field-level restore | One mistake does not require restarting the form |
| Confirm undo/redo from old → new | Restore is itself a data change |

Pair it with the [pre-submit ChangeSummary](/components/change-summary) for the complete loop.

## Trade-off

The cost is one extra click. That is worthwhile in a master form that is mostly read, but not in a create form that is filled from top to bottom. Create mode turns it off with `alwaysEdit` + `trackChanges={false}` so every new field does not turn amber.

## Counterexamples

<Rules>
  <Do><p>View and edit are the<strong> same screen</strong>; only the individual field changes state. The user’s model is “I am editing this field.”</p></Do>
  <Dont><p>Do not switch the whole page between “view mode” and “edit mode.” It forces an Edit → change → Save transaction boundary onto the interface.</p></Dont>
</Rules>

<Rules>
  <Do><p>Use the<strong> reserved amber</strong> to mark changes; it has one meaning everywhere.</p></Do>
  <Dont><p>Do not make an illuminated Save button the only cue. Users know something changed but not which field—especially after a five-minute interruption.</p></Dont>
</Rules>

## Implementation

Use [EditableField](/components/editable-field) + [ChangeSummary](/components/change-summary) + `useRecordDiff`. One `FieldSpec[]` declaration drives comparison, display formatting, and audit records.
