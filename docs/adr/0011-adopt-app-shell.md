# ADR-0011：收錄應用外殼元件（AppShell／Sidebar）與指令面板——修訂 ADR-0008 的外殼排除

- **狀態**：已採用（2026-09-11 結案，見文末後記）；重新檢視條件＝第一個真實宿主依文件自行導入的回報；屆時若決定退場，走〈版本策略〉的棄用流程
- **日期**：2026-08

## 背景

研究 shadcn-admin（MIT，13k+ stars，活躍維護）後決定把它最有價值的部分蒸餾進本書：
表格狀態同步網址、dialog 狀態集中管理、單一導覽資料源同時驅動側邊欄與指令面板，
以及一套成熟的 Sidebar／AppShell 架構。

前三者是模式與 lib，不撞任何既有決策。最後一項正面撞上 ADR-0008：
「Sidebar 則永遠不收——導覽層的正本是模式章的資訊架構那一頁。」

同時，外殼是跨系統不一致成本最高的一塊：三個宿主各自手刻三套側邊欄，
分區規範（模式章〈後台系統的資訊架構〉）就只是三份「盡量遵守」的文件。
這正是這套系統要消滅的東西。

## 選項

| 選項 | 說明 |
| --- | --- |
| A. 維持 0008 | 只把 shadcn-admin 的外殼架構寫成模式文件，元件庫不收 |
| B. 整則取代 0008 | 頁面章邊界一併重開 |
| C. 修訂 0008 的外殼排除，其餘邊界原封 | 外殼以純呈現元件進**元件章**；頁面章的規約不動 |

## 決定

**採 C，且先落在 dev（部署 /preview/）評估去留，再決定是否併入 main。**

1. 修訂範圍**僅限** ADR-0008 理由第 4 點的「Sidebar 則永遠不收」與其選項 C 否決中的
   外殼部分。以下邊界**原封不動**：`packages/react/src/pages/` 只准放 `.stories.tsx`、
   頁面章不發任何 registry item、行為級規範證據由元件自己的 story 承擔、
   其他缺件仍走 RFC＋三次法則。
2. Sidebar／AppShell 以**純呈現元件**進元件章：不綁路由（連結以 `renderLink`／`asChild`
   注入，預設渲染真 `<a>`）、不綁資料抓取、不碰儲存（開闔持久化交宿主）。
   **IA 規範的正本仍是模式章的〈後台系統的資訊架構〉**——元件是規範的載體，
   不是第二份規範；分區判準、單一出口、深連結的規則以那一頁為準。
3. 相依政策：`cmdk`（指令面板）進 boundary 白名單並**單檔隔離**於
   `packages/react/src/ui/command.tsx`，逐字比照 `@xyflow/react` 的前例
   （隔離守衛、build-registry 相依推導、AGENTS.md 大相依提醒）。
   不為 cmdk 另立 ADR——它與外殼是同一個動機的同一批決定。
4. token 層新增 8 個 shadcn 相容的 `--sidebar-*`，其中**只有 `--sidebar` 是新顏色**
   （目標 ΔE00 反解），其餘七個全是別名：`sidebar-ring ≡ ring`（ADR-0007 不重開）、
   `sidebar-primary/accent 家族 ≡ brand/brand-subtle 家族`（識別層色相預算內，
   **零新增色相出口**）。別名恆等由 verify:color 守衛。
5. **三次法則明言未滿足，不粉飾。** 證據現況＝一個外部成熟範本＋缺件表零認領，
   不是三個宿主的重複需求。補償機制：
   - **時間盒**：preview 評估期 4–6 週，或兩個取用端實際試裝，取先到者。
   - **去留判準**（①的措辭於 2026-08-19 修正，理由見下方「判準①的措辭修正」）：
     - ① **收斂證據**，兩條都要：(i) 頁面章組合 story 收斂掉的重複手排**處數**；
       (ii) 五種頁型都組得進 `AppShell` 的**可執行**組合 story。
     - ② 至少一則真實宿主回饋。
     - ③ `verify:storybook` 無障礙守衛全綠。
   - **退場清單**（評估不過時執行）：刪除外殼相關 registry item 與元件檔、
     還原 0008 的狀態註記、收回 `--sidebar-*` token——tokens 0.7.0 的 npm 發佈
     **壓在 dev→main 合併之後**，正是為了讓收回不構成取用端的破壞性變更。

## 理由

1. **「等三個宿主各自手刻三套側欄再收」的代價，正是這套系統要消滅的東西。**
   外殼是使用者每天看八小時的那塊畫面，也是〈後台系統的資訊架構〉全部規範的落點；
   規範沒有載體，一致性就只能靠自律——治理章寫得很清楚，自律防不了漂移。
2. **但這是策略判斷，不是證據。** 所以狀態是「提議中」、有時間盒、有可執行的退場清單。
   ADR-0008 對投機性抽象的警惕仍然成立——本 ADR 不推翻那個警惕，
   只是判斷外殼這一件的「等三次」成本高於風險。
3. **純呈現的邊界讓退場便宜。** 不綁路由與資料，砍掉時宿主可以在一小時內
   用同一份 token 重寫自己的殼——收錄的賭注被刻意壓小。

### 判準①的措辭修正（2026-08-19）

原文寫的是「頁面章組合 story 改組 AppShell 後**刪除的重複手排行數**」。
要驗收時才發現這句話的前提不成立：五支頁面組合 story **從來沒有手排過外殼**，
它們是裸的 `<div className="mx-auto max-w-5xl space-y-4">`——包進 `AppShell`
只會增加行數，刪不到任何東西。照原文字面執行，這條判準永遠拿不到分子。

真正被重複手排、而且已經漂移的是**頁首**（八處，證據見 ADR-0008 後記）。
所以判準①拆成兩條：(i) 用頁首的收斂處數當可量測的分子，
(ii) 外殼的部分改成「五種頁型組得進去」的可執行 story——那本來就是這條判準
想確認的事（殼與頁型相容），只是原文挑錯了量尺。

**記錄這件事而不是默默換一個指標**：偷偷把判準改成比較好過的形式，
與「為了美感放寬無障礙門檻」是同一種錯（見 CLAUDE.md 的門檻優先序）。
判準②（真實宿主回饋）維持原樣，沒有被這次修正碰到。

### 內部試裝（2026-09）

`apps/host-v4` 是本 repo 內照取用端的路接上來的 Tailwind v4 應用：registry 抄進外殼三件與五種頁型需要的元件，
`SidebarNav` 的 `renderLink` 注入 react-router 的 `Link`，`CommandPalette` 與側欄共用同一份 `NavGroup[]`；
`scripts/verify-host.mjs` 驗六主題×兩模式的外殼配色、五頁各一個 h1、頁面級 axe、行動版抽屜的鍵盤焦點歸還。
回饋記在 `apps/host-v4/LEDGER.md`：BackLink 不吃路由元件、表格網址狀態的 prefix 沒有隔離寫入、
FormField 包不了 Select、清單頁「整列可點＋批次勾選」的巢狀互動、shadcn CLI 會刪掉檔頭註解，
以及手機上凍結欄透出。六項都在合併前的同一版處理（見 CHANGELOG v0.13.0 對應的工作項），宿主裡的繞道已經拿掉。

**它不計入判準②。** 內部試裝是同一個作者、同一個 repo、照著自己寫的文件接——
它能提早暴露缺陷，證明不了「別人照文件接得上」。判準②仍等第一個子系統依文件自行導入的回報。

### 2026-09：合併先於評估

時間盒到期時，判準①③已滿足、判準②仍是 0 筆。而「preview 評估通過才併 main」這個順序
在零取用端時是自鎖的：main 停在 0.11.1，唯一的 token 宿主連 0.7.0 都裝不到，
也就不會有子系統來試裝、不會有回饋。維護者決定**先合併、在 main 上評估**，
本則狀態維持「提議中」跨過這次發佈。

順序改變帶來三條修正。記錄下來，而不是默默換規則——與判準①的措辭修正同一種紀律：

1. **退場從「整組收回」改為棄用流程。** tokens 0.7.0 會發佈到 npm，`--sidebar-*` 與外殼元件
   一旦被取用就不能無痕收回。評估不過時：元件與 token 標 `@deprecated`、保留至少一個 minor、
   下一個 major 移除（〈版本策略〉的淘汰流程）。
2. **評估在 main 上進行。** 證據兩層：`apps/host-v4`（內部試裝，弱證據，見上一節）
   與第一個依文件自行導入的子系統（真實宿主）。
3. **時間盒改綁事件而不是日期。** 第一則真實子系統的導入回報結案時，本則改「已採用」
   或啟動上述棄用流程。判準②的文字不變。

## 影響

- 元件章新增：Sidebar 家族、SidebarNav、AppShell、Popover、DropdownMenu、
  Collapsible、Separator、Command／CommandPalette、ConfirmDialog。
  缺件表的「Drawer／Popover／DropdownMenu」列改為「Drawer」單獨列。
- `@dooping/tokens` 0.6.0 → 0.7.0（新增 `--sidebar-*`）；規範 0.11.1 → 0.12.0。
- Storybook 元件分類新增「外殼」；`3-components/00-overview` 的「不收什麼」改寫為
  「外殼的**路由與資料**仍不收」；`5-pages/00-overview` 的兩處外殼敘述同步改寫。
- ADR-0008 加狀態註記（正文不動——ADR 是歷史紀錄）。

## 後記（2026-09-11）：結案為已採用

判準①③已滿足；判準②（真實宿主回饋）在零取用端時無法產生，繼續掛著只會讓本則永遠停在「提議中」——
這正是把計畫寫進決策紀錄的代價。內部試裝抓到的六項缺口已全部在同一版修掉，元件與 token 隨 v0.13.0 發佈。
本則改記為已採用；判準②不刪，改成**重新檢視條件**：第一個真實宿主依文件自行導入的回報進來時，
重新檢視外殼元件是否留用，決定退場就走〈版本策略〉的棄用流程，不會無預警消失。
