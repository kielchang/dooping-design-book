# 決策紀錄（ADR）

這裡是 ADR 的**正本**。文件站的「決策紀錄」章是由 `book/scripts/sync-adr.mjs`
在 build 前自動同步過去的副本——單一來源，兩個出口。

## 什麼時候要寫 ADR

- 這個決定**有人會不同意**
- 這個決定**很難改回來**
- 這個決定**看起來很怪**，未來的人會想「為什麼不用比較直覺的做法」

不符合以上任一條的決定，寫在程式碼註解裡就好。

## 格式

```markdown
# ADR-NNNN：一句話標題

- **狀態**：已採用 / 已取代（→ ADR-XXXX）/ 提議中
- **日期**：YYYY-MM

## 背景
## 選項
## 決定
## 理由
## 影響
```

檔名 `NNNN-kebab-case-title.md`，編號不重用。

## 「提議中」從哪裡來、往哪裡去

「提議中」的 ADR 來自**已接受的 RFC**（issue）：守門人把 RFC 標成 `rfc:已接受` 時
開立 ADR（背景段連回該 issue），實作 PR 合併時由守門人改成「已採用」。
被婉拒的 RFC 不寫 ADR——理由留在 issue。RFC 的入口與狀態機見文件站
「治理 → 回饋與 RFC 流程」（正本 `book/docs/7-governance/02-rfc.mdx`）。
