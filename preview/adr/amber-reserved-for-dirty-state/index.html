ADR-0002：琥珀色保留給「已改動未送出」

  • 狀態：已採用
  • 日期：2026-07

背景​

早期版本沿用試算表的儲存格慣例，把表格欄位分成三色：

  • 橘＝使用者輸入
  • 黃＝公司自訂假設
  • 藍＝公式計算

同時，「使用者改了但還沒送出」的欄位也想用一個顯眼的暖色標示。

結果是：畫面上有三種暖色淡底，彼此難以分辨，而且沒有人分得出「橘」和「黃」的差別。 更糟的是使用者根本不在乎某一格背後是不是公式——他只在乎能不能改。

選項​

選項說明
A. 保留三色，另找一個色標示「已改動」畫面上會有四種暖色
B. 欄位收斂成「可編輯 / 唯讀」兩種，琥珀專用於「已改動未送出」色彩總數減少，語意變清楚
C. 已改動不用顏色，改用圖示標記掃視效率差，一眼看不出改了幾格

決定​

採 B。

  • 欄位語意只分兩種：--field-editable（淡冷底＋清楚邊框）、--field-readonly（muted）
  • 琥珀 --edit / --edit-bg / --edit-foreground 保留給「已改動未送出」，不得挪作他用

可編輯欄位刻意用冷色，與暖色的狀態語意（warning/danger）及琥珀（已改動）拉開距離。

理由​

  1. 試算表慣例對網頁表單不成立。 使用者的問題是「我能不能改這格」， 不是「這格背後是輸入還是公式」。
  2. 「已改動未送出」是最需要被看見的訊號。 它必須獨佔一個顏色， 否則在一片暖色裡就消失了。
  3. 三個暖色淡底實測難以分辨。 這不是理論問題，是實際使用者回報的。

影響​

  • 舊的 col-input / col-assumption / col-formula 三色 class 收斂成兩個。
  • 任何人想用琥珀做別的強調時，必須先推翻這則 ADR。
  • 「已改動未送出」的視覺是三件套（邊框＋底色＋文字色）＋「已變更」文字標籤—— 顏色不是唯一線索。
